Opt-in OS isolation for agent tool shells: `--isolate-shells <user>` (or `ROADIE_ISOLATE_SHELLS`) runs every bash tool call as the given unprivileged user. Roadie generates a wrapper at `<dataDir>/bin/isolated-shell/bash` (mode 0755, root-owned) that uses util-linux `setpriv` (`--reuid`, `--regid`, `--init-groups`, `--no-new-privs`) to drop to the agent user and `env -i` to replace the environment with a fixed allowlist — `PATH` (fixed value), `HOME` (the agent user's home), `TERM`, `LANG`, plus the `ROADIE_*` attribution vars, `ROADIE_SESSION_ID` and `ROADIE_AGENT_TOKEN` from the scoped-endpoints work. Nothing else is inherited: `ROADIE_DB_*`, `ROADIE_SERVICE_TOKEN_FILE`, `ROADIE_AGENT_TOKEN_SECRET` and provider keys never reach a tool shell, and the OpenCode server's `/proc/<pid>/environ` becomes unreadable to the agent. The bot must run as root or with `CAP_SETUID`/`CAP_SETGID` on Linux with `setpriv` available and fails fast at startup otherwise; a doctor-style check reports when project directories are not agent-writable (shared group plus setgid) or private paths are agent-readable. Off by default: with the flag unset, `SHELL` and the generated OpenCode config are unchanged.
