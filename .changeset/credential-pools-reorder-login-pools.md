Credential pools: `/credentials` gains a `reorder` subcommand and `/login` writes into pools when `--credential-pools` is on (issue #137, items 3-4). `/credentials reorder account:<id> position:<n>` moves an account to a 1-based position in the pool order — the tiebreaker the router uses between accounts of the same rotation entry — applied under the pool lock (`movePoolAccount`), with `/credentials list` now numbering accounts so positions are visible; every reply stays ephemeral and never contains a key or token. With pools on, `/login` never touches OpenCode's `auth.json`: the provider picker lists the models.dev catalog (popular ids first, then alphabetical, paginated), Anthropic offers both a Claude subscription (OAuth) and an API key account type, and the writes reuse the exact `/credentials` handlers — `startCredentialsApiKeyModal` (the add-key modal, keys never an option or a reply) and `startCredentialsAnthropicOAuth` (authorize URL + paste modal, ephemeral) — so target-pool resolution and the stricter shared-pool admin rule are identical, and per-person callers manage their own pool while `shared` stays admin-only. With pools off, `/login` is byte-for-byte unchanged.
