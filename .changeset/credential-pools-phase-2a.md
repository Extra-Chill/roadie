Credential pools phase 2a: per-person pool routing (opt-in; the default stays `global` and with `--credential-pools` off nothing changes). Start with `--credentials per-person|per-person-fallback` (or `ROADIE_CREDENTIALS`, implies `--credential-pools`) and `--thread-billing owner|speaker` (or `ROADIE_THREAD_BILLING`, default `owner`). The person key is the identity hook's `person_id`, else `<platform>:<actorId>`; the pool id is the key itself when it is a valid pool id, otherwise a deterministic `person-<sha256 prefix>` hash (never case-folded, so distinct person ids never share a pool), and the hook can now send an optional validated `credential_pool` to override a person's pool (hooks without it behave as before). The first human speaker of a session owns it (insert-or-ignore in a new `credential_owners` table; sessions with no actor bill to `shared`, forks get the forker), the current speaker's resolved pool is recorded per turn in a new `session_actors.credential_pool` column (added by startup migration for existing databases), and the `chat.headers` hook sends the billed person's pool — owner under `owner` billing, the turn's speaker under `speaker` billing — as an ordered comma-separated `x-roadie-pool` list (`per-person-fallback` appends `shared`). `makePoolFetch` tries each listed pool's candidates in order with per-pool cooldowns and fails closed (a failed owner/speaker lookup sends no pool rather than billing `shared`) with `no usable accounts in pool <id>; add one with roadie credentials ... --pool <id>` when every listed pool is empty or cooling down. `roadie credentials list|add-key|login anthropic|remove|rotation set` take `--pool <id>` (default `shared`). Global mode never reads the database and sends exactly today's headers; the generated OpenCode config is unchanged with the flags off.
