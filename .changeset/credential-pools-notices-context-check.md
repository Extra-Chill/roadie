Credential pools: speaker-billing payer-change notice, a context-window check, and operator docs (issue #137, items 5-6). Speaker billing: when a thread's payer first changes — the current turn's billing pool differs from the previous turn's — the thread now posts exactly one notice saying that earlier messages in the thread are sent to the new payer's provider account. The claim is a new `credential_payer_notices` sqlite table (new table, no migration; written insert-or-ignore before posting), so the notice posts at most once per session, never on later turns or after a restart; it is skipped outside speaker billing, in global mode, and when credential pools are off, and an identity-hook `credential_pool` override counts (the same override pool on two speakers is not a change). The pool router also skips a candidate whose model's context-window limit from the models.dev catalog is smaller than the request's estimated input size (~4 chars/token over the serialized prompt and tools), so a long thread rolls to a larger model instead of failing mid-hand-off; unknown limits, a failed catalog load, and an unserializable prompt never skip, and when every candidate is too small the 401 says so with the estimate. Docs: new `docs/credential-pools.md` for operators and users — modes and thread billing (including the speaker-billing costs: cache loss, reasoning not crossing providers, privacy), `/credentials` and `/login` with pools on, the identity hook `credential_pool` override, any-provider API keys via the models.dev catalog with `baseURL` overrides, Anthropic subscriptions, `import-subrouter`, turn affinity, and a Security section covering the phase 1-2 trust model (an agent with shell can read `<dataDir>/credentials`; per-person servers should deny the `shell` capability to non-admins via the identity hook).
