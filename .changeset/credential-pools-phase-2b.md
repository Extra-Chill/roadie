Credential pools phase 2b: a `/credentials` Discord command for managing your own pool (registered only when `--credential-pools` is on, so servers with pools off see no change and `/login` is untouched). Subcommands: `list` (accounts with provider, type, label, access-token expiry and cooldowns, plus rotations — never keys or tokens), `add-key` (the API key is only ever entered in a modal, never a slash-command option), `login-anthropic` (OAuth authorize URL plus a button that opens a modal to paste `code#state` or the full redirect URL, with pending PKCE state held in memory under a random hash with a 10-minute TTL), and `remove` (by account id). Every reply is ephemeral and no key, token or key fragment is ever echoed; modal-submit handlers re-resolve the target pool and re-check permissions from the interaction instead of trusting the first click. Target pool: per-person modes default to the caller's own pool resolved by the new shared `resolvePersonBillingPool` helper (the same one turn routing uses, so they can never disagree), `pool:shared` — and the default target in `global` mode — writes the shared pool and requires the stricter credential-pool admin (identity-hook `admin` capability when a hook is configured, otherwise Discord Administrator or Manage Server; a non-admin can never target any pool except their own). When an account is added to a rotationless pool, the shared pool's rotations are copied into it under the same names under the pool lock, only if it still has none, so `roadie/<rotation>` requests never 401 for a fresh person pool.
